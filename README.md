# MH Sidebar

Нативная боковая панель мониторинга для Windows 10/11 x64, написанная на Rust. Проверенная клиентская конфигурация v0.5.0 — Windows 11; статус остальных сценариев приведён в матрице совместимости. В v0.5.1 добавлены автозапуск с правами администратора и настройка порядка показателей внутри блоков. Интерфейс в стиле MH Monitoring: Cuprum, тёмные карточки, бирюзовый акцент и живой предпросмотр.

## Запуск

Запустите `MH-Sidebar.exe` из каталога сборки (`dist/v0.5.1/`) или распакованного `MH-Sidebar-v0.5.1-windows-x64.zip`. Обычный ручной запуск не требует установки и прав администратора. При первом запуске откроются настройки: выберите монитор, сторону и ширину, затем нажмите **Готово**. Автозапуск с повышенными правами включён по умолчанию; Windows запросит UAC при сохранении настроек. Если отказаться от повышения, настройки останутся открытыми и автозапуск не будет включён. По умолчанию панель выбирает второй монитор (или основной, если экран один).

- Левый клик по значку в трее — показать/скрыть панель.
- Правый клик — настройки, блокировка кликов, перезапуск датчиков, выход.
- **Ctrl+Alt+F11** — показать/скрыть; **Ctrl+Alt+F10** — пропускать клики; **Ctrl+Alt+F12** — настройки. Сочетания настраиваются.
- Кнопка `×` на панели скрывает её. Для завершения используйте **Выход** в трее.
- Колесо мыши прокручивает длинную панель. В режиме пропуска кликов управление доступно через трей/хоткеи.
- «Зарезервировать пространство» оставляет место для панели при разворачивании окон. Выключено по умолчанию.
- Автозапуск настраивается в разделе «Общие» через задачу Планировщика Windows для текущего пользователя: вход в систему запускает EXE интерактивно с правами администратора без повторного UAC. Учётная запись Windows должна иметь права администратора; при вводе учётных данных другого пользователя создание задачи отменяется. Старый автозапуск через `HKCU\...\Run` переносится при первом запуске обновлённой версии. После переноса EXE выключите и снова включите автозапуск, чтобы обновить путь в задаче.

## Показатели

| Блок | Источник и показания |
|---|---|
| CPU | Загрузка, логические потоки, частота по данным ОС. Эта частота не является измерением мгновенного boost каждого ядра. |
| GPU NVIDIA | NVML из установленного драйвера: загрузка, температура, частоты, VRAM, мощность, вентилятор. |
| Другие GPU | WDDM/PDH: загрузка, VRAM и те датчики температуры/частот/вентилятора, которые предоставляет драйвер. |
| ОЗУ | Занято, доступно, всего и процент использования. |
| Диски | Объём томов, занятое место, чтение/запись через PDH. Процент — заполнение тома, не активность диска. |
| Сеть | Приём и передача отдельно для каждого интерфейса, включая виртуальные. В настройках можно выбрать нужные устройства. |

Память отображается в GiB, скорости — в MiB/s. Недоступные данные не заменяются нулями; причина видна в настройках устройства. Начальные скорости появляются после двух замеров. «Скрывать недоступные показатели» управляет видимостью таких строк на панели. Пороговые цвета настраиваются отдельно для температуры CPU и GPU. В v0.4 доступны настраиваемые уведомления Windows; звук приложение не воспроизводит.

Температура и мощность CPU читаются через драйвер [PawnIO](https://pawnio.eu) (AMD Ryzen Zen 1–5 и Intel с цифровым датчиком). Драйвер ставится отдельно — кнопкой «Установить PawnIO» в настройках процессора (через `winget`) или с сайта; открыть его может только администратор, поэтому там же есть кнопка «Перезапустить от имени администратора». В exe встроены только подписанные модули PawnIO `AMDFamily17` и `IntelMSR` (см. `assets/pawnio/NOTICE.md`); с `PawnIOLib.dll` программа не линкуется. SMART/температура дисков и скорость модулей RAM в v0.2 не поддерживаются. Программа не включает WinRing0, LibreHardwareMonitor, PresentMon, службу или инъекции.

## Совместимость и выпуск v0.5

- Пакет выпуска находится в отдельном каталоге версии и ZIP-архиве. В него входят EXE, README, матрица совместимости, отчёт проверки и тексты лицензий; `SHA256SUMS.txt` проверяет каждый файл пакета. Сборочный скрипт сверяет версию EXE и архитектуру x64, не заменяя предыдущие выпуски.
- Проверена Windows 11 25H2 с двумя мониторами: 150% DPI на основном и 125% на дополнительном. Резервирование места справа и слева, скрытие и освобождение рабочей области прошли на обоих экранах. Windows 10, физическая смена дисплеев и DPI, сон/пробуждение и перезапуск Explorer остаются отдельными пунктами проверки. Подробная матрица — в `COMPATIBILITY.md` внутри пакета и `docs/COMPATIBILITY.md` в репозитории.
- Скрипт `tools/measure-resources.ps1` измеряет CPU, память, дескрипторы и потоки отдельного тестового экземпляра с изолированными настройками. Результат текущего ПК и условия замера записаны в матрице; они не являются гарантией потребления на другом оборудовании.

## Надёжность v0.1.1

- В разделе предупреждений — отдельные пороги CPU и GPU. При загрузке настроек v0.1.0 прежние значения используются как начальные для обоих блоков; затем меняются независимо. В v0.1.1 добавлено необязательное поле `cpu_temperature`; в v0.2 применяется схема JSON 2, описанная ниже.
- После трёх последовательных замеров без температуры **и** мощности CPU приложение освобождает датчик и пробует открыть его заново. Задержки — 1, 2, 4, 8, 16, затем максимум 30 секунд; попытка выполняется на ближайшем цикле опроса. Успешное чтение хотя бы одного показателя сбрасывает задержку.
- Отсутствие только одного показателя не вызывает переоткрытие. Неподдерживаемый процессор автоматически не перепроверяется; команда «Перезапуск датчиков» в трее начинает проверку заново.
- В состоянии CPU-датчиков видны причина недоступности, ожидание повторной попытки и давность последнего успешного чтения температуры или мощности. Подробности также доступны в подсказках недоступных строк.
- Восстановление работает для завершившихся вызовов драйвера. В v0.2 источники работают в независимых потоках; зависший системный вызов не прерывается, но не задерживает остальные источники и завершение интерфейса.

## Аналитика v0.4

- Нажмите на название блока или показатель в панели, чтобы открыть увеличенный график за выбранный интервал истории. Там показаны текущее значение, состояние источника, число доступных замеров, минимум, среднее арифметическое и максимум. Наведение на график показывает время и значение ближайшей точки. Пропущенные и устаревшие замеры остаются разрывами.
- В окне графика можно сохранить CSV выбранного показателя или всех показателей, сохранившихся в истории текущего сеанса. Экспорт содержит время Unix в миллисекундах, время от запуска в секундах, блок, ID и имя устройства, показатель, подпись, единицу и значение. Отсутствующие значения остаются пустыми. История ограничена выбранным интервалом и не сохраняется автоматически между запусками. Активный файл настроек нельзя выбрать для экспорта.
- В разделе «Предупреждения» можно включить уведомления Windows и добавить правила по блоку, показателю и при необходимости устройству. Для каждого правила задаются порог, время непрерывного превышения и пауза между повторными уведомлениями. Устаревшие и недоступные показания уведомления не вызывают. По умолчанию уведомления выключены; цветовые температурные пороги работают независимо от них.
- Схема настроек 4 хранит правила и переключатель уведомлений. При миграции старого файла сохраняется точная резервная копия `settings.v1.json`, `settings.v2.json` или `settings.v3.json`; если копия с таким именем уже содержит другие данные, создаётся отдельная копия с отметкой времени. Старые версии приложения не перезапишут схему 4.

## Удобство v0.3

- В разделе «Профили» доступны минимальный, игровой и рабочий варианты, сохранение собственных профилей, обновление по имени и удаление. Профиль сохраняет оформление, часы, блоки и выбор устройств; монитор, автозапуск, видимость, горячие клавиши и температурные пороги остаются текущими.
- Импорт JSON заменяет только черновик. «Применить» сохраняет его, «Отмена» отбрасывает изменения. Экспорт сохраняет черновик через стандартный диалог Windows; выбрать текущий файл настроек для экспорта нельзя. Импорт принимает файлы до 1 МиБ и отклоняет неизвестную будущую схему.
- В «Показателях» блоки можно перетаскивать за ≡; стрелки также доступны. В «Внешнем виде» выбирается компактная, обычная или свободная плотность строк.
- В «Горячих клавишах» нажмите «Записать нажатием», затем сочетание; Esc отменяет запись, «Очистить» отключает действие. На время записи глобальные сочетания панели снимаются и восстанавливаются при завершении, отмене или потере фокуса. Системные сочетания Windows и сочетания других программ могут перехватываться ими; остаётся ручной ввод (Win записывается как `Super`).
- Схема настроек 3 хранит профили и плотность. Перед миграцией создаётся `settings.v1.json` или `settings.v2.json`; существующая копия сохраняется. Версии v0.1/v0.2 не перезапишут файл схемы 3. Для возврата используйте соответствующую резервную копию.

## Устройства и сбор данных v0.2

- Шесть независимых источников: CPU ОС, CPU/PawnIO, RAM, GPU, диски и сеть. Один задержавшийся источник не блокирует остальные. Для каждого показываются состояние и давность замера; устаревшие показания заменяются на «—» только у этого источника (после трёх интервалов опроса, минимум 5 секунд).
- Выбор устройства и история привязаны к ID, а название служит подписью. Для томов используется GUID тома, для сети — InterfaceGuid, для GPU — путь устройства Windows; NVML и WDDM сопоставляются по PCI-адресу. Если постоянный ID недоступен, настройки явно предупреждают об ограничении. При отсутствии сопоставления GPU NVML использует UUID; автоматическое объединение с WDDM в таком случае не гарантируется.
- При отключении устройства его карточка и график остаются с пометкой «Отключено» до окончания выбранного окна истории. Возвращение того же ID продолжает график с разрывом. Результат одного замера не добавляется повторно при перерисовке. История хранится только в памяти сеанса.
- Начиная со схемы 2 выбор устройств хранится в `device_ids`. Старые названия из `devices` переносятся при однозначном совпадении; отсутствующие или неоднозначные остаются в ожидании сопоставления. При одинаковых моделях GPU выбор нужно подтвердить вручную.
- Сеть собирается через Windows IP Helper: активные физические и виртуальные интерфейсы, без loopback и служебных фильтров драйвера. Счётчики скорости привязаны к GUID, поэтому переименование не создаёт новый график. Обнаружение изменений сети выполняется при опросе; инвентаризация GPU/томов — раз в 30 секунд.
- «Перезапуск датчиков» ставит перезапуск в очередь каждого существующего потока. Дополнительные потоки для зависшего источника не создаются. Если системный вызов не вернётся, восстановление этого источника потребует перезапуска приложения; остальное продолжит работать.

## Настройки

`%APPDATA%/MH Sidebar/settings.json`. Изменения в окне сначала видны в предпросмотре; **Применить** сохраняет их, **Отмена** отбрасывает. Порядок блоков и показателей внутри каждого блока меняется перетаскиванием или стрелками. Значения потоков CPU перемещаются одной группой. Для каждого блока можно выбрать устройства, видимые строки и показатель графика; история — 30–300 секунд.

Повреждённый JSON сохраняется в `settings.corrupted-<timestamp>.json`; более новая схема не перезаписывается. Запись файла выполняется через временный файл и атомарную замену. Приложение не отправляет телеметрию и не проверяет обновления по сети.

## Сборка и проверки

Требуются Rust stable с MSVC toolchain и Windows SDK / Visual Studio Build Tools (C++).

```powershell
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo run --locked --example probe
cargo run --locked --example collection_probe
cargo test --locked --lib -- --ignored --nocapture
cargo run --locked --example dock_probe
cargo run --locked --example compatibility_probe
powershell -ExecutionPolicy Bypass -File tools/gui-smoke.ps1
powershell -ExecutionPolicy Bypass -File tools/measure-resources.ps1
powershell -ExecutionPolicy Bypass -File tools/build-release.ps1
powershell -ExecutionPolicy Bypass -File tools/verify-release.ps1 -PackageDirectory dist/v0.5.1 -ExpectedVersion 0.5.1
```

`dock_probe` кратковременно резервирует место на втором экране и проверяет восстановление; `--primary` проверяет основной экран. Оба диагностических примера включают Per-Monitor V2 DPI awareness. `dock_probe` нужно запускать в обычном сеансе рабочего стола: изолированная песочница без доступа к Explorer отклоняет AppBar.

`gui-smoke.ps1` требует предварительного `cargo build`; он использует отдельный конфиг в `target/gui-smoke`, проверяет Reset/Cancel, открытие настроек с панели, Reset/Apply и скрытие. На время кликов собственное окно выводится наверх, проверяется адресат клика и восстанавливается позиция курсора. Тест завершается остановкой только своего процесса.

Для отдельной тестовой конфигурации: `MH-Sidebar.exe --config "C:/path/settings.json" --settings`. `--smoke-test 15` завершает процесс через 15 секунд. В debug-сборке переменная `MH_SIDEBAR_CAPTURE_DIR` включает локальные снимки только собственных окон; в релизе этого кода нет.

## Проверенная конфигурация и ограничения

На машине разработки проверены Ryzen 9 5900X, RTX 5070 Ti, чтение NVML/WDDM, диски и сеть; реальный AppBar справа/слева, скрытие/возврат и освобождение рабочего стола. Геометрия с отрицательными координатами и дробным DPI покрыта тестами.

Физическое отключение мониторов, смена DPI во время работы и перезапуск Explorer требуют дополнительной ручной проверки на разных системах. Обработчики этих событий реализованы. Боковая панель задач Windows слева/справа может перекрывать нерезервирующую панель: в этом случае включите резервирование. Доступность GPU-показателей зависит от драйвера. Совпадение ID между NVML и WDDM проверено на RTX 5070 Ti; несколько физических GPU, отключение оборудования и смена букв томов требуют отдельной ручной проверки.

Релиз не подписан Authenticode; отсутствие предупреждений SmartScreen/антивируса не гарантируется. EXE не упаковывается UPX. Контрольная сумма находится в `SHA256SUMS.txt` рядом с EXE.
